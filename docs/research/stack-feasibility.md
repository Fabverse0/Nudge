# Evaluasi Kelayakan Stack Nudge

Tanggal pemeriksaan: 18 Oktober 2026. Catatan ini memakai dokumentasi resmi Next.js, Tailwind CSS, MDN, WebKit, dan spesifikasi W3C.

## Rekomendasi

Finalisasikan stack inti MVP sebagai **Next.js App Router + TypeScript + Tailwind CSS + PWA manifest/service worker + `localStorage` untuk favorit**. Kombinasi ini sesuai untuk satu aplikasi web responsif yang dapat dipasang di ponsel. Next.js mendukung manifest lewat konvensi App Router dan mendokumentasikan pola PWA; TypeScript didukung langsung; Tailwind memiliki panduan integrasi resmi untuk Next.js. [Next.js PWA](https://nextjs.org/docs/app/guides/progressive-web-apps), [Next.js TypeScript](https://nextjs.org/docs/app/getting-started/installation), [Tailwind CSS + Next.js](https://tailwindcss.com/docs/installation/framework-guides/nextjs)

Untuk MVP tanpa akun atau sinkronisasi cloud, katalog aktivitas dapat menjadi data lokal aplikasi dan favorit kecil dapat disimpan di `localStorage`. Data ini tersimpan per origin pada browser dan bertahan lintas sesi biasa, sehingga bukan sinkronisasi lintas perangkat. Mode privat dapat menghapusnya saat sesi ditutup, dan kebijakan browser dapat mencegah penyimpanan. Karena browser API hanya tersedia di sisi klien Next.js, akses `localStorage`, timer interaktif, dan izin notifikasi harus berada di Client Components. [MDN: `localStorage`](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage), [Next.js: Server dan Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components)

Manifest dan service worker mendukung instalasi serta fungsi PWA, tetapi instalasi memerlukan HTTPS dan dukungan prompt berbeda antarplatform; panduan Next.js menyebut prompt kustom `beforeinstallprompt` tidak lintas platform dan tidak bekerja di Safari iOS. [Next.js: PWA dan instalasi](https://nextjs.org/docs/app/guides/progressive-web-apps)

## Batas penting: pengingat saat aplikasi tertutup

Jangan menjanjikan notifikasi lokal terjadwal yang tepat waktu saat Nudge tertutup. Notifications API menampilkan notifikasi ketika dipanggil; notifikasi persisten dapat dibuat melalui service worker, tetapi worker dapat dihentikan saat idle dan tidak mempertahankan state prosesnya. Periodic Background Sync juga tidak cocok sebagai alarm: browser menentukan waktunya berdasarkan kondisi seperti engagement, baterai, dan jaringan. [MDN: Notifications API](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API), [MDN: ServiceWorkerGlobalScope](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerGlobalScope), [Chrome: Periodic Background Sync](https://developer.chrome.com/docs/capabilities/periodic-background-sync)

Web Push dapat membangunkan service worker ketika aplikasi tidak sedang terbuka, tetapi pesan datang dari server melalui layanan push browser. Artinya, pengingat tertutup yang opt-in memerlukan pengirim push/backend dan penyimpanan subscription, meskipun produk tetap tanpa akun atau sinkronisasi data pengguna. Di iOS/iPadOS, Web Push berlaku untuk web app yang ditambahkan ke Home Screen dan permintaan izin harus menyusul tindakan langsung pengguna. Pengiriman push juga tidak menjamin waktu presisi. [MDN: Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API), [Next.js: PWA dan Web Push](https://nextjs.org/docs/app/guides/progressive-web-apps), [WebKit: Web Push di iOS/iPadOS](https://webkit.org/blog/13878/), [Chrome: Notification Triggers](https://developer.chrome.com/docs/web-platform/notification-triggers)

**Keputusan produk yang perlu dicatat di PRD:** pertahankan MVP tanpa backend dan batasi pengingat pada penggunaan saat aplikasi aktif; atau izinkan layanan backend pengirim push untuk pengingat saat tertutup. Dalam kedua pilihan, notifikasi harus opt-in, dapat diubah/dimatikan, dan mengikuti izin browser. Tanpa keputusan kedua, stack inti tetap layak; fitur pengingat tertutup belum termasuk cakupan yang dapat dijanjikan.
